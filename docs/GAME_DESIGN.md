# 랜덤 스파이어 기획서

> 메이플 랜덤 디펜스식 **랜덤 소환·합성 디펜스**에 슬레이 더 스파이어식 **로그라이크 진행**(갈림길 맵, 전투 후 증강 선택, 유물, 대가 있는 선택)을 합친 모바일 웹 게임.
> 아이폰 사파리 세로 화면 기준, 도트 그래픽.

- 플레이: `docs/index.html` 을 브라우저로 열면 바로 실행 (파일 하나, 오프라인 가능)
- 한 판: 약 15~20분, 3막 × 7층, 전투 11~13회

## 1. 핵심 루프

```
[맵] 갈림길에서 다음 칸 선택
  ├ 전투 / 엘리트 / 보스 ─→ [전투] 소환·합성·배치로 웨이브 3개 버티기 ─→ [보상] 골드 + 증강 1개(엘리트·보스는 유물도)
  ├ 이벤트 ─→ 대가를 치르고 보상을 얻는 선택
  ├ 상점   ─→ 유물·소모품·증강 구매, 저주 제거
  ├ 휴식처 ─→ 생명 회복 또는 클래스 수련
  └ 보물   ─→ 유물
3막 보스(균열의 군주)를 쓰러뜨리면 클리어. 생명이 0이 되면 모험 끝.
```

전투 안에서는 랜덤 디펜스의 손맛(뽑기 → 3개 모아 합성 → 등급 상승)을, 전투 밖에서는 로그라이크의 빌드 설계(어떤 증강·유물을 모을지, 어느 길로 갈지)를 즐기는 구조다. **유닛·골드·생명·강화 레벨은 모험 내내 이어진다.**

## 2. 전투 규칙

| 항목 | 규칙 |
|---|---|
| 보드 | 4×5 = 20칸. 한 칸에 **같은 유닛(클래스+등급) 3기까지** 쌓인다 (최대 60기) |
| 길 | 보드를 둘러싼 사각 루프. 적은 왼쪽 위 균열 문에서 나와 시계 방향으로 **계속 돈다** |
| 누수 | 적이 한 바퀴를 돌아 균열 문을 지날 때마다 생명 감소 (일반 1, 엘리트 3, 보스 6). 적은 사라지지 않고 계속 돈다 |
| 필드 상한 | 필드에 적이 **60마리**가 되면 즉시 패배 (성능 상한 역할도 겸함) |
| 소환 | 골드로 무작위 클래스 일반 유닛 소환. 비용 = 10 + 지금까지 소환 횟수 (모험 전체 누적). 5% 희귀, 0.5% 영웅 |
| 합성 | 같은 칸의 같은 유닛 3기 → **다음 등급의 무작위 클래스** 1기. 일반 → 희귀 → 영웅 → 전설 |
| 배치 | 끌어서 자리 바꾸기. 바깥 14칸은 길과 26px, 안쪽 6칸은 52px 떨어져 있어 **근접(전사·도적)은 바깥, 원거리는 안쪽**이 유리. [정리] 버튼이 자동 배치 |
| 표적 | 사거리 안에서 가장 멀리 간 적(누수 직전)부터 공격 |
| 웨이브 | 전투당 3웨이브, 16초 간격. 필드를 일찍 비우면 1.2초 뒤 다음 웨이브 + 빠른 정리 보너스 골드 |
| 골드 | 처치 골드(막마다 ×1/×1.6/×2.2) + 웨이브 시작 골드(6/10/14) + **이자**(보유 10골드당 1, 최대 5) + 클리어 보상 |
| 강화 | 클래스별 레벨당 피해 +15% (모든 등급에 적용). 비용 30 + 20×레벨 |
| 판매 | 현재 소환 비용 × 0.4 × 3^등급 |
| 보스 | 보스 등장 후 75초 제한. 넘기면 **폭주**(속도 ×1.8, 누수 피해 ×2) |
| 상성 | 돌골렘·흑기사: 가벼운 물리(궁수·도적) 50% 감소 / 유령: 물리 40% 감소 / 리치: 물리 25% 감소 |

**선택의 긴장 포인트**
- 골드를 바로 쓸까(소환·강화), 모아서 이자를 받을까, 상점까지 들고 갈까
- 합성 결과가 무작위라 배치가 계속 흐트러진다 → 매번 재배치 판단
- 보드가 차면 소환 대신 강화, 또는 낮은 등급 판매

## 3. 로그라이크 구조

- **맵**: 막마다 7층 × 3갈래. 1층 전투, 4층 보물, 6층 휴식처, 7층 보스 고정. 2·3·5층은 무작위(2층 전투 70/이벤트 30, 3층 전투 40/이벤트 25/엘리트 15/상점 20, 5층 전투 35/이벤트 20/엘리트 30/상점 15). 막마다 상점 최소 1개 보장
- **보상**
  - 일반 전투: 골드 + 증강 3개 중 1개 (등급 확률 1막 실버70/골드27/프리즘3 → 3막 48/40/12). 건너뛰면 골드
  - 엘리트: 골드 + 증강(골드·프리즘 위주) + 유물 2개 중 1개
  - 보스: 골드 + 프리즘 증강 + 희귀·보스 유물 3개 중 1개, 다음 막으로 넘어가며 생명 25% 회복
- **대가 있는 선택**: 증강·유물·이벤트 곳곳에 "강한 효과 + 명확한 대가"를 섞었다 (피의 계약: 피해 +35% / 최대 생명 -5, 유리 대포: 피해 +80% / 누수 피해 2배 등). 슬더스처럼 생명을 자원으로 쓰게 만드는 장치
- **빌드 축**: 경제(이자·현상금·미다스), 합성 운(행운의 합성·도박꾼의 주사위·고대 두루마리·거울), 클래스 특화(훈련 증강 + 강화 + 순수 혈통), 조건부(다양성·정예주의·부자의 여유·광전사), 위치(전쟁 깃발=모서리, 확대경=안쪽)
- **저장**: 칸을 옮길 때마다 자동 저장. 전투 도중 나가면 같은 시드로 그 전투를 처음부터 다시 한다

## 5. 밸런스 설계

### 수치 모델
- 적 체력: `64 × 성장률^L` (L = 웨이브 레벨 = 3×(진행 층-1) + 웨이브 번호, 0~62). 성장률은 막마다 **1.105 / 1.078 / 1.065**. 후반으로 갈수록 보드가 차고 소환 비용이 올라 플레이어 성장도 느려지기 때문에, 한 가지 성장률로는 3막이 과하게 어려워졌다 (시뮬레이터로 확인)
- 초반 완충: L이 낮을 때는 체력을 60%부터 서서히 100%로 올린다 (첫 전투 튜토리얼 구간)
- 보스 체력은 "평균 빌드의 DPS × 약 8" 근처에 맞췄다. 보스는 한 표적이라 전체 DPS의 약 20%만 들어가므로(유닛마다 길의 일부만 사거리에 들어옴), 평균 빌드면 **한 바퀴 안팎**에 잡히도록 했다

### 시뮬레이터 (`node tools/sim.js [판수] [smart|random]`)
실제 게임 로직(`game/src/core`)을 그대로 Node에서 돌려 봇이 수백 판을 플레이한다.
- **smart 봇**: 증강 점수표로 고르기, 생명이 낮으면 엘리트 회피, 자동 합성·소환, 보드가 차면 가장 많은 클래스 강화, 5초마다 자동 배치
- **random 봇**: 증강·유물·길·이벤트를 무작위로 고르고 배치를 하지 않음

최종 결과 (smart 500판 / random 300판):

| | smart 봇 | random 봇 |
|---|---:|---:|
| 클리어율 | **30.2%** | 3.7% |
| 1막에서 사망 | 12.6% | 49.7% |
| 2막에서 사망 | 34.6% | 39.0% |
| 3막에서 사망 | 22.6% | 7.7% |

선택을 잘하면 8배 가까이 더 깬다 → **선택이 결과를 좌우**하는 로그라이크가 됐다. 사람은 봇보다 이자 관리·배치·상성 대응을 잘할 수 있으므로 숙련자 체감 클리어율은 이보다 높을 것으로 본다.

smart 봇 기준 전투 유형별 평균 생명 손실 / 평균 전투 시간:

| 막 | 일반 전투 | 엘리트 | 보스 |
|---|---:|---:|---:|
| 1막 | -0.3 / 36초 | -2.2 / 60초 | -5.1 / 74초 |
| 2막 | -1.6 / 50초 | -4.1 / 71초 | -4.2 / 72초 |
| 3막 | -1.5 / 53초 | -2.6 / 67초 | -3.5 / 68초 |

클래스별 피해 비중 (smart): 전사 22% · 궁수 22% · 마법사 22% · 도적 22% · 서리술사 12%(둔화 보조). 배치를 안 하는 random 봇은 근접(전사·도적) 비중이 3막에서 10%·9%로 떨어진다 → **배치가 실제로 중요**하다.

### 조정 이력 (시뮬레이터로 찾은 문제와 수정)
1. 첫 버전: 일반 전투 승률 100%·생명 손실 거의 0, 반면 보스에서 대부분 사망 → 일반 적 체력 ×2.1, 보스 체력 배율 대폭 하향(55→7.5 등)
2. 3막만 유독 어려움 → 플레이어 DPS 성장이 막마다 느려지는 것을 확인, 체력 성장률을 막별로 분리
3. 보스전 생명 손실이 체력을 깎아도 줄지 않음 → 원인은 **보스가 뱉는 졸개**였다. 보스 위치(이미 한 바퀴 거의 다 돈 곳)에서 풀체력 슬라임 10마리가 나와 바로 누수 → 분열·소환 졸개 체력 50~60%, 수 감소
4. 2막 보스(리치)가 최대 사망 지점 → 체력 8→7

## 6. 모바일(아이폰 사파리) 성능 설계

- **논리 해상도 160×186** 캔버스 하나에 그리고 CSS로 확대 (`image-rendering: pixelated`). 기기 물리 픽셀의 정수배로 맞춰 도트가 고르게 보이게 함
- 스프라이트는 코드 안의 문자 도트맵을 시작할 때 한 번 캔버스로 구워 두고 `drawImage`만 사용. 외곽선은 굽는 단계에서 자동 생성, 등급 색은 팔레트 교체로 4벌
- 로직은 **1/60초 고정 스텝**, 배속(×2·×3)은 스텝 수만 늘림. 한 프레임 최대 12스텝으로 저사양에서 폭주 방지
- 적 60마리 상한(규칙 겸 성능 상한), 투사체 90개·숫자 16개 상한, 유닛은 공격 시점에만 표적 탐색
- 전투 로직과 화면을 분리: 로직은 이벤트만 쌓고 렌더러가 소비. 같은 코드가 Node 시뮬레이터에서도 돈다
- DOM(HUD)은 0.1초마다, 값이 바뀐 곳만 갱신
- 화면이 가려지면 자동 일시정지, 전투 중 화면 꺼짐 방지(Wake Lock, 지원 시)
- 픽셀 한글 폰트 **Galmuri11**(OFL)을 게임에 쓰는 600자만 남겨 서브셋 → 14KB. 전체 빌드 약 200KB 한 파일
- iOS 대응: 세이프 에어리어, 더블탭·핀치 확대 방지, 롱프레스 메뉴 방지, 터치 끝(touchend)에서 오디오 잠금 해제, 가로 화면 안내
